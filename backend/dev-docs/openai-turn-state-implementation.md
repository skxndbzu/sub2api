# OpenAI 会话状态管理：实施与使用说明

本功能适用于 OpenAI OAuth 账号，默认关闭。配置保存在账号 `extra.openai_turn_state`，状态及刷新计划保存在现有 Redis；不需要新增数据库表。实际效果尚未进行真实上游灰度验证。

## 启用

1. 在账号创建、编辑或批量编辑中展开“会话状态探测与注入”配置。
2. 选择现有代理节点、实际发往上游的模型 ID，以及需要使用的服务档位；未携带档位对应 `omitted`。每个模型/档位独立缓存。本期只探测显式选中的组合。
3. 开启功能并保存。编辑已保存的账号时可点击“立即探测”，观察各模型/档位的状态、来源代理、摘要、采样时间和剩余 TTL。
4. 需要输出完整状态时，另行勾选“打印上游响应状态原值”并保存。此开关独立于探测/注入开关，可单独用于排查。

批量编辑只更新勾选的配置字段，保留其余设置。“立即探测”“清空缓存”使用已保存的账号配置，不使用编辑界面尚未保存的值。清空使在途旧任务失去提交资格；后续业务未命中或手动操作可以发起新任务。

| 参数 | 默认值 |
| --- | --- |
| 目标状态长度 | 292 |
| 缓存 TTL | 3600 秒 |
| 提前刷新 | 600 秒 |
| 一轮最大候选节点 | 10 |
| 单候选探测超时 | 20 秒，含出口检查及 SSE 请求 |
| 自动失败冷却 | 60 秒起，指数增加，最高 600 秒；尊重更长 Retry-After |

代理必须具备不同且固定的公网出口。每个候选使用相同代理访问两次 `https://chatgpt.com/cdn-cgi/trace` 检查上游站点观察到的 IP；重复、不可确认、轮换出口跳过，不发起该节点的状态请求。两次检查不能证明供应商下一连接绝不换 IP，供应商仍须配置固定出口。最多检查前 N 个已选节点；重复出口占候选预算。程序不生成 IPv6，不修改账号业务代理。

## 原值日志

账号开关开启后，实际 HTTP/SSE、插件传输、账号测试、探测 SSE 和 WS 握手响应中的字段输出为 INFO 事件：

```text
event/message: openai_turn_state_upstream_response
account_id: <账号 ID>
transport: http | http_plugin | account_test | probe_sse | ws_pool_handshake | ws_passthrough_handshake
state_length: <原值长度>
state_digest: <短摘要>
x-codex-turn-state: <上游实际返回的完整原值>
```

`x-codex-turn-state` 是响应头，不是 JSON 响应体字段。日志不从响应体查找同名字段，不输出注入缓存值作为“上游返回值”。重复响应头按实际值分别记录。

也可在服务进程环境中设置 `OPENAI_TURN_STATE_LOG_VALUES=true`，全局启用 OpenAI OAuth 原值日志。通过容器部署时必须将变量传入容器环境；仅写宿主机 `.env` 而不在容器配置中引用不会生效。关闭全局变量后，账号开关仍独立生效。未开启时仅输出 DEBUG 长度/摘要，不输出原值。其他凭据、代理密码和用户内容不进入新增日志。

常规诊断事件包括 `openai_turn_state_probe_match`、`openai_turn_state_probe_finished`、`openai_turn_state_probe_candidate`、`openai_turn_state_cache_hit`、`openai_turn_state_cache_miss` 和 `openai_turn_state_cache_unavailable`。缓存命中/未命中和候选细节使用 DEBUG，成功探测与轮次结果使用 INFO。

## 请求与生命周期

- 缓存键严格由账号行 ID、最终上游模型、最终有效服务档位组成。同组合跨用户/线程共享，不共享对话正文。
- 固定最小探测正文；不带客户端历史状态、文件或工具记录。收到成功 SSE 头后立即关闭响应体，原值校验合格才保存。关闭流不代表上游没有执行或没有用量。
- 普通 HTTP、自动透传、WS 转 HTTP 在最终出站阶段注入。有效缓存覆盖客户端历史值，保留现有账号来源校验。换账号重新读取，原始客户端请求头保持独立。
- HTTP/WS 业务响应返回任何长度均不写共享缓存，不延长 TTL。仅真实响应值按原有协议逻辑回传客户端。
- WS 握手注入；池连接的兼容条件包括账号、模型、档位、身份、缓存代际和状态摘要。首选连接或容量不足不能绕过条件。等待、拨号及预热重新校验。
- 已借出的 WS 不因刷新、到期或清空被强制中断。新请求不能将旧握手连接作为新缓存命中复用。已建立的受管会话改变模型/档位时拒绝该帧并返回 `turn_state_route_changed`，客户端应另建连接；原连接仍可继续原目标。
- Redis 中维护刷新时间索引；每 15 秒扫描到期任务，每分钟核对账号及修复计划。默认约第 50 分钟开始刷新；故障或队列压力可能延迟。刷新失败保留旧值至原到期时间，绝不自动续期。
- 账号与模型共用分布式租约，不同档位串行探测。每实例 4 个 worker、256 项队列，业务不等待探测；Redis 缓存读取使用 30 ms 上下文预算，故障降级到原有转发。
- 身份/指纹/功能配置变化和清空缓存通过代际使旧结果不能写回。普通 OAuth token 轮换不改变稳定身份摘要。父账号身份变化同时处理凭据影子账号。
- 服务重启重新读取共享缓存、刷新计划及账号配置。状态数据遵循 Redis 自身持久化策略；Redis 数据丢失后重新探测，不假装缓存仍可用。
- 关闭账号功能后停止新注入和新探测，已发出的探测结果不能提交，现有 WS 自然结束。原值日志由独立开关控制。

## 管理接口

以下接口位于现有管理员账号路由及鉴权下：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/v1/admin/accounts/:id/turn-state/status` | 按模型/档位返回状态与诊断，不返回原始状态 |
| `POST /api/v1/admin/accounts/:id/turn-state/probe` | 异步探测；JSON `{}` 表示所有已选目标，可提供 `model`、`service_tier` |
| `DELETE /api/v1/admin/accounts/:id/turn-state/cache` | 清空已选缓存，可用查询参数指定 `model`、`service_tier` |

## 本地验证范围

新增测试覆盖：312 拒绝、292 完整选中、收到头后 SSE 关闭；账号/模型/档位隔离；HTTP 与自动透传注入优先级和换号；业务真实响应不覆盖缓存/续期；到期回退；分布式竞争、清空及身份失效屏障；旧数据库快照不能重新启用缓存；刷新计划跨客户端恢复与单消费者领取；WS 握手注入、连接池代际/模型硬隔离和不兼容帧处理；原值日志开关；控制台默认值、批量补丁、操作接口和错误提示。

Redis 测试使用 miniredis，HTTP/SSE 使用本地模拟上游，WS 使用模拟拨号器/帧连接，不访问真实账号上游。真实 Redis 故障切换、多网关部署、供应商固定出口、跨线程共享效果和成本收益需要后续部署环境验证。设计文档的完整验收矩阵是后续部署验证目标，不应将本地测试视为已完成全部矩阵。
